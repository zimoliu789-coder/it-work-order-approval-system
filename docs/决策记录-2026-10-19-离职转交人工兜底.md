# 决策记录 · 2026-10-19 · 离职转交：保留自动转交 + 补人工兜底

> 相关需求：`docs/改造方案-2026-10-16-八项需求.md`「转单规则定稿 · 边界」——
> 「执行人**离职不自动转单**，由本组管理员手动操作」
> 相关实现：`OrderTransferServiceImpl#transferOnDimission`、`MessageType#DIMISSION_TRANSFER_FALLBACK`

## 一、冲突是什么

需求那句「离职**不**自动转单」与系统既有能力相反：

| 既有实现 | 需求文字 |
| --- | --- |
| `TransferType.AUTO_DIMISSION`：标记离职时，把该员工名下的在办工单**自动转给**同组其他在职成员（负载最少优先、并列随机） | 执行人离职**不**自动转单，由**本组管理员**手动操作 |

两者只能取其一，或取一个折中。批次 2 交付时刻意**没有改动**这条自动路径
（静默撤销一个已经在跑的能力，风险大于收益），把它挂账，等明确裁决。

## 二、裁决（2026-10-19，用户选 B）

**B · 保留自动转交，把需求那句话理解为「自动转交做不了时的人工兜底」。**

推理链：

1. 自动转交的实际价值在于「离职那天单子就有人接」——撤掉它，等于把一批工单直接扔进无人区；
2. 需求真正想防的，是「自动机制把人安排到不合适的人头上」以及「无人可安排时没人管」。B 保留前者、补上后者；
3. 因此需要落地的是一个**失败时的出口**，而不是删掉成功路径。

## 三、落地方式

`transferOnDimission` 的行为（能转就转、转不了就喊人）：

| 情形 | 处理 |
| --- | --- |
| 同组有其他在职成员 | 自动转交（原逻辑不动），历史记录类型 `AUTO_DIMISSION`，通知新执行人 |
| 同组**无**其他在职成员 | 计入 `skipped`；除原有 `log.warn` 外，**发一条 P1 告警**（`DIMISSION_TRANSFER_FALLBACK`）给全部超管 |
| 条件 UPDATE 命中 0 行（并发下已归还 / 已被他人转交） | 计入 `skipped`，**不告警**——这类单子已不在离职账号名下，没有待处置动作 |

告警正文包含：离职员工、失败工单清单（单号 + 状态 + 归属小组）、三条可执行动作
（强制转交执行人 / 超管代发同组转单 / 强制终止）、以及根治建议（给小组补人或调整归属）。

**一次离职只发一条告警**：离职常一次带出十几笔在办单，逐单告警会淹没消息中心。

## 四、为什么兜底只通知超管，不通知「本组管理员」

这是本轮侦察出的关键事实 —— 需求文字里的「本组管理员手动操作」在现有权限模型下**做不到**：

| 动作 | 谁可以做 | 依据 |
| --- | --- | --- |
| 人工转交 `transfer` | 本人是当前执行人，或 super_admin | `OrderTransferServiceImpl#transfer` |
| 同组转单 | 发起人必须是**当前执行人**（super_admin 可代发） | `OrderTransferRequestServiceImpl#createSameGroup` |
| 跨组转单 | 仅本组管理员 / super_admin，且目标小组需配管理员 | `#createCrossGroup` |
| 强制转交执行人 | `order:force:manage`（超管级权限码） | `OrderForceOperationController` |

而此刻工单挂在**已禁用**的离职账号上 —— 于是「本组管理员」既不是当前执行人、也没有强制干预权限，
**发给他等于把工单推进死胡同**。所以收件人只保留真正能动手的超管，正文直接写清点哪里。

> 若将来要真正把这件事交给本组管理员，需要新增授权（例如允许组管理员对本组离职单发起代转），
> 那是独立的一次权限设计，不在本次裁决范围内。

## 五、验证

- 单测：`OrderTransferServiceImplTest`
  - 组内无人 → `skipped=1` 且发出 `P1 / DIMISSION_TRANSFER_FALLBACK` 告警，正文含失败单号；
  - 全部转交成功 → 不发告警（避免狼来了）；
  - 部分成功 + 部分失败 → 告警只列失败那笔，不混入已转交的单。
- 门禁：后端全量 `mvn test` + 前端 `type-check / vitest / build`。

## 六、上线后自检（NAS）

1. 找一个小组成员少于 2 人的处理小组，让该组唯一成员离职；
2. 期望：离职弹窗仍提示「已转待收回 N 台设备」，并且超管消息中心收到一条「离职工单待人工转交」；
3. 点进去按告警正文走「强制转交执行人」，确认工单执行人变更且时间线留痕。
